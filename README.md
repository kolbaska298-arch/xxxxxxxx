# Void legion анкеты

Это бот приёма анкет в Void legion.

## Возможности

- анкета с именем, возрастом и фото скина;
- сохранение анкет в SQLite;
- уведомление администраторов о новой анкете;
- кнопки «Принять» и «Отклонить»;
- просмотр ожидающих анкет через `/applications`;
- после принятия пользователь получает ссылку-приглашение в Void legion;
- отказ блокирует пользователя в боте;
- отдельная блокировка без отказа и разблокировка через кнопку администратора.

## Запуск на Windows

1. Установите Python 3.11 или новее.
2. Откройте PowerShell в папке проекта и создайте окружение:

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

3. Скопируйте `.env.example` в `.env`.
4. Создайте бота через [@BotFather](https://t.me/BotFather) и вставьте токен в `BOT_TOKEN`.
5. Узнайте Telegram ID администраторов и укажите их через запятую в `ADMIN_IDS`.
6. Запустите:

```powershell
python bot.py
```

Администраторы должны сначала открыть диалог с ботом и нажать `/start`, иначе Telegram не разрешит боту отправлять им уведомления.

После изменения кода перезапустите бота. Блокировка действует внутри этого бота: Telegram не позволяет боту блокировать пользователя во всех чатах Telegram.

## Запуск в контейнере или на хостинге

Файл `.env` не хранится в репозитории. В настройках сервиса добавьте переменные окружения:

```text
BOT_TOKEN=токен_от_BotFather
ADMIN_IDS=8414885700
```

После добавления переменных выполните redeploy/restart контейнера. Также поддерживается имя `TELEGRAM_BOT_TOKEN` вместо `BOT_TOKEN`.

Docker-образ запускает бота от непривилегированного пользователя `botuser`, не копирует `.env` и хранит базу в `/data`.

### Railway

Откройте проект Railway, перейдите в **Variables** и добавьте:

```text
BOT_TOKEN=токен_от_BotFather
ADMIN_IDS=8414885700
```

Затем нажмите **Deploy** или **Redeploy**. Если в логах остаётся текст `Не задан BOT_TOKEN в файле .env`, Railway запускает старый деплой: нужно заново задеплоить актуальный `bot.py`.

## Защита кода и секретов

- Сделайте GitHub-репозиторий **Private** и выдавайте доступ только доверенным участникам.
- Включите двухфакторную аутентификацию GitHub и Railway.
- Не добавляйте `.env`, токены, SQLite-базу и логи в Git. Они уже исключены в `.gitignore` и `.dockerignore`.
- Храните `BOT_TOKEN` и `ADMIN_IDS` только в Railway Variables или локальном `.env`.
- Если токен уже публиковался, сначала отзовите его через `@BotFather`, затем создайте новый.
- Защитите ветку `main`: запретите прямой push и включите обязательный review.

Python-код нельзя полностью скрыть от владельца Railway или человека с доступом к контейнеру: приложение должно читать его во время запуска. Обфускация может только усложнить чтение и не защищает от изменения кода. Реальная защита исходников достигается приватным репозиторием, ограничением доступа и секретами вне репозитория.
